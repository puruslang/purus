# Issue tracker

How issues are handled in this repository.

- Work is tracked as GitHub issues; branch and open a pull request that references the issue (`Closes #N`).
- Templates: bug report, feature request, task. Language proposals use the feature request form and must include the Purus source and the JavaScript it should compile to.
- Labels: `bug`, `enhancement`, `refactor`, `performance`, `documentation`, `question`, `good first issue`, `help wanted`, `epic`, and the areas `area: compiler`, `area: tooling`, `area: release`, `area: repo-rules`, `area: docs`, `area: editor`, `area: ai`, `area: ecosystem`.
- `epic` issues (#28, #51) are tracking lists; close them when every item is done.
- A language change is not complete until the follow-up issues for the linter, prettier plugin, editor grammar, language server and docs exist.
